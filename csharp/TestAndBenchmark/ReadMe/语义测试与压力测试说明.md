# 语义测试与压力测试说明

## 一、这组测试验证什么

语义测试与压力测试用于验证 `ConcurrentExclusiveLock`、`ConcurrentExclusiveLockScope` 和 `ConcurrentExclusiveLockPipeline` 的**协议正确性与长期稳定性**。

它关注的是：

> 锁在并发竞争、升级、降级、失败、异常和长时间运行后，是否仍然遵守既定访问权限协议。

它不用于比较不同锁的性能，也不以吞吐量高低作为通过条件。

测试主要通过公开 API 进行黑盒调用，并使用专用 `Thread` 制造真实竞争。测试过程中持续执行断言；任意权限重叠、释放错误、线程异常或超时都会使测试失败。

`ObservedState` 和 `ObservedContention` 是观察快照，不作为建立同步正确性的依据。

---

## 二、主要测试模式

### `--advanced-correctness`

高级权限转换专项测试。

重点验证：

- `ExclusiveToConcurrent` 降级后的连续访问语义；
- `ConvergeConcurrent` 的收敛过程；
- Concurrent → Exclusive 条件升级；
- 失败者的 Concurrent 自动释放；
- 升级赢家与普通 Exclusive 之间的调度关系；
- 大量独立锁同时运行时，各锁之间是否保持隔离。

该模式支持显式指定锁数量、每锁任务轮数和随机种子。

### `--full-semantics`

全语义回归测试。

测试会先执行确定性的访问契约，再执行模型驱动的随机合法路径，覆盖：

- Concurrent / Exclusive 基础获取与释放；
- 抢占式 Exclusive；
- Exclusive → Concurrent 降级；
- Concurrent → Exclusive 升级；
- ContextID / EpochID 条件升级；
- Scope 生命周期与异常释放；
- Pipeline 权限状态转换；
- 同一持有链上的反复升级与降级。

随机状态机只生成符合公开协议的调用路径，测试目标是验证实现，而不是故意调用未定义或非法用法。

### `--pipeline-semantics`

Pipeline 的固定批次语义测试。

用于验证不同 Segment 组合之间的权限延续、切开、升级、降级和失败处理，包括：

- 独立 Concurrent / Exclusive 段；
- Try 类型段；
- `ConvergeConcurrent`；
- `ConvergeExclusive`；
- 以 ContextID / EpochID 为条件收敛到 Exclusive；
- Try 条件失败后以 None 状态继续；
- Pipeline 结束或异常退出时的最终释放。

### `--pipeline-stress <duration>`

Pipeline 的按时间随机压力测试。

每个批次会随机生成：

- 独立锁数量；
- 每把锁的专用线程数；
- 每把锁的 Pipeline 执行轮数；
- Segment 数量与组合；
- 空业务段和极短临界区；
- 随机种子。

该模式适合发现低概率的权限转换、状态衔接和异常释放问题。失败时应保留输出的 seed，用相同参数复现对应批次。

Pipeline 位于核心锁和 Scope 之上。随机 Segment 组合会实际调用普通 Concurrent、普通 Exclusive、Try 获取、升级、降级、业务 ID 条件收敛和失败释放等底层路径，因此在当前测试体系中，**长时间运行 `--pipeline-stress` 一般就能覆盖主要权限协议和三层 API 的组合行为**。

日常验证不必把所有长时间模式都跑一遍。先完成一次确定性语义测试后，通常再让 Pipeline 随机压测运行数小时即可；发布收口或重大修改后，再根据需要延长到 24 小时或更久。

这里所说的“覆盖”是指主要访问权限与转换协议。超时重载、观察快照、单锁极端竞争、持久锁对象资源趋势等专项问题，仍由对应测试模式补充验证。

### `--endurance <duration>`

长期耐久度测试。

测试开始时创建一批锁对象，之后所有批次持续复用这些锁，不通过反复重建锁对象掩盖长期状态问题。

锁数量和线程拓扑会根据逻辑处理器数量自动选择。测试持续覆盖多类合法调用路径，并定期报告：

- 累计批次和操作进度；
- 归一化 CPU；
- 工作集与私有内存；
- 托管内存；
- 线程数量；
- GC 次数；
- 各调用路径分布。

此模式只接收测试时长，不接收锁数量、线程数量或操作量参数。按 `Ctrl+C` 后，会请求在当前批次结束后正常停止并输出最终结果。

### `--contention-stress <duration>`

单锁高竞争诊断测试。

用于在大量专用线程竞争同一把锁时观察竞争压力和长期运行行为。它属于专项压力测试，不用于不同锁之间的性能排名。

## 三、核心检查内容

测试会根据具体模式检查以下一项或多项规则：

1. Exclusive 业务区不得与任何 Concurrent 或其他 Exclusive 业务区重叠。
2. Concurrent ID 必须位于有效范围内，同一轮同时持有的 ID 必须唯一。
3. Concurrent → Exclusive 条件升级必须符合唯一赢家或业务 ID 推进规则。
4. 条件升级失败后，原 Concurrent 必须按照协议自动释放。
5. Exclusive → Concurrent 降级必须遵守连续访问和升级调度规则。
6. Scope 在正常释放、提前返回和异常路径后都必须正确结束持有状态。
7. Pipeline 必须按照 Segment 模式正确切换、延续或释放权限。
8. Try 类型段未获得执行条件时，当前段必须被跳过，并从 None 状态继续。
9. 每轮或每批结束后，锁必须回到可继续使用的状态。
10. 任意测试失败后，输出必须包含足够的批次和随机种子信息用于复现。

## 四、运行参数

### 通用语义参数

| 参数 | 含义 |
|---|---|
| `--lock-instances` | 独立锁数量。不同锁之间互不共享状态。 |
| `--semantic-workers` | 每把锁使用的专用 Thread 上限，至少为 2。 |
| `--semantic-operations` | 每把锁执行的语义路径或 Pipeline 轮数上限。 |
| `--semantic-seed` | 可选随机种子。指定后可复现相同随机调用形状。 |

在随机压力模式中，实际锁数量、每锁线程数和每锁轮数可能在 `1..N` 或测试定义的有效范围内随机选择。因此这些参数通常表示随机形状的上限，而不是每个批次都固定使用该值。

### 高级专项参数

| 参数 | 含义 |
|---|---|
| `--advanced-operations` | 每把锁、每类高级操作的基准任务轮数。 |
| `--advanced-seed` | 高级专项测试的可选随机种子。 |

大量独立锁模式会为每把锁创建固定数量的专用线程，并在多轮任务中复用这些线程。

### 时间参数

以下格式均可用于持续时间：

```text
30s
10m
24h
1d
hh:mm:ss
```

`--pipeline-stress` 后必须给出持续时间。

`--endurance` 后只给出持续时间，其他拓扑参数由程序自动决定。

---

## 五、失败与复现

任意断言失败、线程异常或超时都会立即终止当前测试，并返回非零退出码。

随机测试失败时通常会输出：

- batch 编号；
- 随机 seed；
- 本批锁数量、每锁线程数和轮数；
- 失败路径或异常链。

复现时应保持测试模式和主要参数不变，仅将输出中的 seed 传给对应的 `--semantic-seed` 或 `--advanced-seed`。

---

## 六、推荐执行顺序

第一次验证发布包时，建议按以下顺序执行：

1. 先运行一次全语义回归，确认确定性契约全部通过；
2. 再运行 Pipeline 固定语义测试；
3. 运行 10 分钟 Pipeline 随机压测，确认命令和随机批次能够稳定执行；
4. 日常收口时，让 Pipeline 随机压测持续运行数小时；
5. 发布或重大修改后，可将 Pipeline 压测延长到 24 小时或更久。

在当前测试体系中，Pipeline 随机压测已经通过 Scope 调用核心锁，并覆盖主要的获取、释放、升级、降级、Try 失败和业务 ID 收敛路径。因此，**一般不需要把所有压力模式都长时间运行一遍，跑数小时 `--pipeline-stress` 就可以作为主要压力验证**。

`--endurance`、`--contention-stress` 和大量独立锁专项测试用于补充持久锁对象、资源趋势、单锁峰值竞争或特定拓扑，不是每次修改后的必跑项目。

快速测试通过只能说明主要路径没有立即失败；长时间随机压测用于扩大调度顺序、Segment 组合和运行时间覆盖，不能替代确定性语义测试。

## 七、直接运行命令

```powershell
# 查看全部命令行选项
.\TestAndBenchmark.exe --help

# 高级权限转换专项测试
.\TestAndBenchmark.exe --advanced-correctness

# 大量独立锁的高级权限转换测试
.\TestAndBenchmark.exe --advanced-correctness --lock-instances 1000 --advanced-operations 4 --advanced-seed 12345

# 全语义回归
.\TestAndBenchmark.exe --full-semantics --lock-instances 64 --semantic-workers 4 --semantic-operations 256

# Pipeline 固定语义测试
.\TestAndBenchmark.exe --pipeline-semantics --lock-instances 1 --semantic-workers 64 --semantic-operations 1000 --semantic-seed 12345

# Pipeline 随机压力测试：10 分钟冒烟
.\TestAndBenchmark.exe --pipeline-stress 10m --lock-instances 8 --semantic-workers 64 --semantic-operations 1000 --semantic-seed 12345

# Pipeline 随机压力测试：一般验证运行 3 小时
.\TestAndBenchmark.exe --pipeline-stress 3h --lock-instances 8 --semantic-workers 128 --semantic-operations 2000

# Pipeline 随机压力测试：发布收口运行 24 小时
.\TestAndBenchmark.exe --pipeline-stress 24h --lock-instances 8 --semantic-workers 128 --semantic-operations 2000

# 可选：长期耐久度测试，观察持久锁对象和资源趋势
.\TestAndBenchmark.exe --endurance 24h

# 单锁高竞争诊断：128 个专用线程，持续 10 秒
.\TestAndBenchmark.exe --contention-stress 10s --threads 128
```
