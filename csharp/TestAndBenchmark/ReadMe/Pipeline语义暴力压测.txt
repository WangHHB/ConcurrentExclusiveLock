Pipeline 语义暴力压测
====================

用途
----

`--pipeline-stress` 用于按时间持续随机压测 ConcurrentExclusiveLockPipeline。

它只测试 Pipeline 语义，不跑普通锁横向性能对比。

如果 Pipeline 压测长期不出错，基本可以认为：

1. 底层 ConcurrentExclusiveLock 的组合语义稳定。
2. ConcurrentExclusiveLockScope 的异常释放和状态还原稳定。
3. ConcurrentExclusiveLockPipeline 的权限切换状态机稳定。


命令
----

固定批次语义测试：

    .\TestAndBenchmark.exe --pipeline-semantics --lock-instances 1 --semantic-workers 64 --semantic-operations 1000 --semantic-seed 12345

短时间冒烟：

    .\TestAndBenchmark.exe --pipeline-stress 30s --lock-instances 4 --semantic-workers 16 --semantic-operations 80 --semantic-seed 13579

单锁高并发：

    .\TestAndBenchmark.exe --pipeline-stress 10m --lock-instances 1 --semantic-workers 128 --semantic-operations 2000 --semantic-seed 12345

多锁中等并发：

    .\TestAndBenchmark.exe --pipeline-stress 10m --lock-instances 8 --semantic-workers 32 --semantic-operations 1000 --semantic-seed 12345

中等压力：

    .\TestAndBenchmark.exe --pipeline-stress 10m --lock-instances 8 --semantic-workers 64 --semantic-operations 1000 --semantic-seed 12345

大批次随机形状：

    .\TestAndBenchmark.exe --pipeline-stress 1h --lock-instances 16 --semantic-workers 128 --semantic-operations 3000

长时间收口：

    .\TestAndBenchmark.exe --pipeline-stress 24h --lock-instances 8 --semantic-workers 128 --semantic-operations 2000

极限长跑：

    .\TestAndBenchmark.exe --pipeline-stress 10d --lock-instances 8 --semantic-workers 128 --semantic-operations 2000

失败批次复现模板：

    .\TestAndBenchmark.exe --pipeline-semantics --lock-instances 4 --semantic-workers 32 --semantic-operations 500 --semantic-seed 123456789


参数含义
--------

`--pipeline-stress`

    指定持续压测时间。
    支持 30s、10m、24h、1d 或 hh:mm:ss。

`--lock-instances`

    每个批次随机使用 1..N 把独立锁。

`--semantic-workers`

    每把锁随机使用 2..N 个专用 Thread。

`--semantic-operations`

    每把锁随机执行 1..N 轮 Pipeline。

`--semantic-seed`

    可选随机种子，用于复现失败批次。
    如果不指定，会自动生成。


压测内容
--------

每个批次都会随机选择：

1. 锁数量。
2. 每锁线程数。
3. 每锁 Pipeline 轮数。
4. Pipeline 段数量和段类型。
5. 是否执行空业务代码。

Pipeline 段会随机覆盖：

1. None
2. Concurrent
3. ConvergeConcurrent
4. Exclusive
5. TryExclusive
6. TryConcurrent
7. TryConvergeExclusive

业务段会随机出现空代码，用于专门压短临界区路径。


失败行为
--------

任意语义错误、权限重叠、线程异常或超时都会立即停止。

失败时会输出：

1. batch 编号。
2. 可复现 seed。
3. 本批 shape：locks x workers/lock x rounds/lock。
4. 异常链。

可以用输出的 seed 复现问题。


推荐最终收口
------------

先跑完整确定性语义：

    .\TestAndBenchmark.exe --full-semantics --lock-instances 1 --semantic-workers 64 --semantic-operations 1000

再跑 Pipeline 长时间随机压测：

    .\TestAndBenchmark.exe --pipeline-stress 24h --lock-instances 8 --semantic-workers 128 --semantic-operations 2000

如果机器核心数很多，可以额外追加单锁高并发：

    .\TestAndBenchmark.exe --pipeline-stress 24h --lock-instances 1 --semantic-workers 512 --semantic-operations 2000

如果要观察多锁实例长期稳定性，可以追加：

    .\TestAndBenchmark.exe --pipeline-stress 24h --lock-instances 64 --semantic-workers 16 --semantic-operations 1000

这两个都稳定后，当前语义层基本可以收口。
